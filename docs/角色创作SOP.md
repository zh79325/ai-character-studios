# 角色创作标准作业流程（SOP）

所有角色创作按本流程执行。三个阶段严格串行，前一阶段未确认不得进入下一阶段。

```
阶段一 角色设定（文字）→ 【用户确认】→ 阶段二 最终渲染图（文生图）→ 阶段三 四视图（图生图）
```

---

## 零、目录与命名规范

```
~/Desktop/{创作者姓名}/
├── 人物姿势模版.jpg              ← 全局共用，四视图排版基准
├── 角色创作SOP.md                ← 本文档
└── {角色名}/
    ├── tmp/                      ← 中间产物：草稿设定、废弃渲染图、重生成的历史版本
    │   ├── {角色名}_渲染图_v1_20260829_160115.png
    │   └── {角色名}_背面_v2_20260829_160116.png
    ├── {角色名}角色设定.md        ← 定稿
    ├── {角色名}_最终渲染图.png     ← 定稿
    ├── {角色名}_正面.png          ← 定稿
    ├── {角色名}_右侧.png          ← 定稿
    ├── {角色名}_背面.png          ← 定稿
    └── {角色名}_左侧.png          ← 定稿
```

规则：
- **第一层只放定稿**，文件名不带版本号、不带时间戳。
- **所有中间/废弃/历史版本一律放 `{角色名}/tmp/`**，文件名带 `_v{N}_{YYYYMMDD}_{HHMMSS}`。
- 定稿被替换时，旧文件移入 `tmp/`，不直接删除。
- 每次生图工具的原始输出先落 `tmp/`，通过校验后再复制到第一层并改成定稿名。

## 阶段一 · 角色设定

### 1.1 产出设定文档

文件：`{角色名}/tmp/{角色名}角色设定_v1.md`，草稿阶段一直在 tmp 内迭代。

必填维度（缺一不可）：

| 维度 | 必须写明 |
|------|----------|
| 基本信息 | 角色名、类型、原创/授权、姿态基准（直立/四足/飞行） |
| 头部 | 角的数量与形态、眼睛颜色与是否发光、牙齿/口部、面部轮廓 |
| 躯干四肢 | 体表材质（鳞/毛/皮）、肌肉体格、手指数、脚趾数、是否着装鞋袜 |
| 附属结构 | 尾巴/翅膀/棘刺的**数量**、位置、形态、是否分离 |
| 颜色质感 | 主色调、受光面高光色、发光部位、材质（哑光/金属/半透明） |
| 整体风格 | 艺术风格、气质、用途 |
| 环境设定 | 栖息环境、光照氛围、可搭配的场景元素（供阶段二背景使用） |

编写要求：
- 一律用具体值，禁止模糊词：「深色」→「深灰黑色」；「发光」→「红色辉光」；「多条尾巴」→「2条，从臀部后方自然垂下」。
- 关键中文特征后附英文关键词，便于直接拼 prompt，如 `双眼发出红色光芒（red glowing eyes）`。

### 1.2 提取硬性约束清单

从设定中抽出**可数、可判定**的项，单独列成清单，后续每一张图都用它逐条校验：

```
硬性约束（赤瞳双尾兽示例）
- 尾巴 = 2 条，彼此分离
- 眼睛 = 红色发光
- 手 = 三指利爪 / 脚 = 三趾带爪、赤足
- 背部棘刺 = 一排，颈部至尾部
- 姿态 = 直立双足
```

### 1.3 【门禁】用户确认设定

将设定文档 + 硬性约束清单交付用户确认。**未获确认不得生图。**

确认后：文档移出 tmp，定稿为 `{角色名}/{角色名}角色设定.md`，草稿版留在 `tmp/`。

## 阶段二 · 最终渲染图（文生图）

**性质：text-to-image，只传 prompt，不传任何参考图。**

### 2.1 拼 prompt

只以定稿设定文档为依据，按固定顺序组织：

```
姿态 → 头部 → 躯干 → 四肢 → 附属结构（写明数量） → 颜色 → 材质 →
环境背景 → 光照 → 艺术风格 → 画质
```

本阶段**鼓励带背景与环境**：栖息地、地形、天气、氛围光、动态姿势、镜头感都可写入，目标是一张有完成度的效果图，而非白底标准图。

### 2.2 生成参数

- 工具：`generate_image`（不带 `image_urls`）
- 尺寸：2048×2048
- 输出先落 `{角色名}/tmp/{角色名}_渲染图_v{N}_{时间戳}.png`

### 2.3 校验并定稿

逐条比对 1.2 的硬性约束清单，任一不符 → 针对该项强化 prompt 后重生成，旧图留在 `tmp/`。

通过后复制到第一层，命名 `{角色名}_最终渲染图.png`。

**此图即角色的唯一视觉标准**，阶段三及后续所有生产均以它为准，不得凭文字重新想象。

---

## 阶段三 · 四视图（图生图）

**性质：image-to-image，必须传入参考图，禁止纯文字生成。**

### 3.1 参考图输入（强制）

每次调用 `generate_image` 的 `image_urls` 必须同时包含：

1. `人物姿势模版.jpg` — 提供视角角度、站姿、排版、白底规范
2. `{角色名}_最终渲染图.png` — 提供角色外观、配色、材质

生图前先用 `understand_media` 解析两张图：
- 姿势模版 → 确认视角角度、站姿、背景样式
- 最终渲染图 → 导出完整外观细节清单，写进 prompt

### 3.2 四视图定义

| 视角 | 定稿文件名 | 关键约束 |
|------|-----------|----------|
| 正面 | `{角色名}_正面.png` | 正对镜头，双臂自然下垂，面部完整可见 |
| 右侧 | `{角色名}_右侧.png` | 身体右转约30°，右臂略前伸，侧面轮廓清晰 |
| 背面 | `{角色名}_背面.png` | 完全背对，背部与附属结构清晰、数量正确 |
| 左侧 | `{角色名}_左侧.png` | 身体左转约30°，与右侧镜像对称 |

姿势模版中的排列顺序（从左至右）：正面 → 右侧 → 背面 → 左侧。

### 3.3 统一约束

与阶段二相反，四视图**必须去掉一切环境元素**：

- 背景：纯白（`Pure white background, no gradient`）或透明
- `negative_prompt` 必须含：`background, grid, shadow on ground, text, watermark, environment, scenery`
- 尺寸：2048×2048
- 四次调用可并行，输出先落 `tmp/`

### 3.4 背面图专项（高发问题）

- prompt 中显式写出附属结构的数量与分离状态，例：`TWO distinct tails, side by side, clearly separated, not merged into one`
- 明确要求纯白底，避免灰白渐变
- 生成后必检：数量对不对、是否粘连、背景是否干净

### 3.5 校验与定稿

| 检查项 | 标准 | 不达标处理 |
|--------|------|-----------|
| 背景纯净度 | 纯白/透明，无网格、渐变、地面阴影 | 重生成，强化背景约束 |
| 附属结构数量 | 与硬性约束清单完全一致 | 重生成，prompt 显式写数量 |
| 附属结构分离度 | 多尾/多肢清晰分开 | 重生成，加 `distinct` `side by side` `not merged` |
| 角色一致性 | 四图与最终渲染图配色、材质、特征一致 | 严重偏差重生成 |
| 视角准确性 | 正/背面完全正对，侧视约30° | 角度偏差过大重生成 |

修正原则：只重生成，不做后期修图；重生成时 prompt 必须针对问题点加约束；旧版本留 `tmp/`。

全部通过后复制到第一层，用定稿名。

## 五、后续使用规范

1. 四视图直接作为 3D 建模 turnaround reference 使用，无需去底。
2. 设定变更 → 更新设定文档 → 重走阶段二、阶段三，被替换的定稿移入 `tmp/`。
3. 任何偏离 `{角色名}_最终渲染图.png` 的产出需经用户确认。
4. 每完成一个角色，把新踩到的坑补进本文档。
