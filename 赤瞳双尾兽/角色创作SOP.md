# 角色创作标准作业流程（SOP）

## 文档定位

本文档是**所有角色创作的通用流程规范**，基于"赤瞳双尾兽"项目实战提炼而成。后续创建任何新角色时，均应按此SOP执行，确保产出物格式统一、质量可控、资产可追溯。

---

## 一、前置准备

### 1.1 角色设定文件

每个角色必须有一份独立的文字设定文档（Markdown格式），作为所有视觉创作的权威依据。

**设定文档应包含的维度：**

| 维度 | 说明 | 示例要素 |
|------|------|----------|
| 基本信息 | 角色名称、类型、版权属性、姿态基准 | 原创/授权、直立/四足/飞行 |
| 头部特征 | 角、眼、口、面部轮廓 | 角的数量/形态、眼睛颜色/发光、牙齿类型 |
| 躯干与四肢 | 皮肤/鳞片/毛发、肌肉线条、手脚结构 | 材质质感、肢体比例、指/趾数量 |
| 附属结构 | 尾巴、翅膀、棘刺等 | 数量、位置、形态 |
| 颜色与质感 | 主色调、高光色、发光部位、材质感 | 哑光/金属/半透明 |
| 整体风格 | 艺术风格、气质定位、用途 | 史诗奇幻/赛博朋克、凶猛/优雅、3D建模参考 |

**存放规范：**
- 设定文件命名：`{角色名}角色设定.md`
- 存放位置：角色专属文件夹根目录
- 版本管理：设定变更需同步更新文档并标注版本号

### 1.2 参考素材准备

- **姿势模板图**：用于确定四视图的排列顺序、视角角度、站姿规范
- **风格参考图**（可选）：若角色有明确对标作品，准备1-2张风格参考

## 二、创作流程

### Step 1 — 读取并解析角色设定

- 读取角色设定Markdown文件
- 提取全部视觉特征参数，形成结构化清单
- **关键动作**：确认不可妥协的硬性约束（如尾巴数量、眼睛颜色、特殊结构），这些将在后续每一步中反复校验

### Step 2 — 生成首张效果渲染图

使用 `generate_image` 工具，以纯文字prompt描述角色全貌：

**Prompt编写原则：**
- 按"整体→局部"顺序描述：姿态→头部→躯干→四肢→附属结构→颜色→材质→风格
- 每个特征用具体形容词，避免模糊表述（"深色"→"深灰黑色"，"发光"→"红色辉光"）
- 明确艺术风格和光影要求

**输出规范：**
- 尺寸：2048×2048（正方形，便于后续裁剪和参考）
- 风格：与设定文档一致
- 文件名：`{角色名}_最终渲染图.png`

### Step 3 — 存档最终渲染图

- 创建角色专属文件夹：`~/Desktop/{创作者姓名}/{角色名}/`
- 将最终渲染图复制至该目录
- **核心原则**：此图为后续所有生产的唯一视觉参考标准，任何偏离需经确认

### Step 4 — 分析姿势模板与角色特征

使用 `understand_media` 分别解析：
- 姿势模板图 → 确认四视图排列顺序、视角角度、背景样式
- 最终渲染图 → 提取完整外观细节清单，作为image-to-image生成的参考依据

**四视图标准排列（从左至右）：**
1. 正面视图（Front View）
2. 右侧视图（Right Profile，身体右转约30°）
3. 背面视图（Back View）
4. 左侧视图（Left Profile，身体左转约30°，与右侧镜像对称）

### Step 5 — 批量生成四视角无背景图

同时调用4次 `generate_image`，每次传入最终渲染图作为 `image_urls` 参考（image-to-image模式）：

**统一约束：**
- negative_prompt 必须包含：`background, grid, shadow on ground, text, watermark`
- 尺寸均为 2048×2048
- 背景要求：纯白或透明，无网格、无渐变、无地面阴影

**各视角关键约束：**

| 视角 | 关键约束 |
|------|----------|
| 正面 | 正对镜头，双臂自然下垂，面部完整可见 |
| 右侧 | 身体右转约30°，右臂略前伸，侧面轮廓清晰 |
| 背面 | 完全背对，背部结构、附属结构（尾巴/翅膀等）清晰可见且数量正确 |
| 左侧 | 身体左转约30°，与右侧镜像对称 |

**️ 背面图特别注意：**
- 必须在prompt中显式强调附属结构的数量和分离状态（如"TWO distinct tails...not merged into one"）
- 背景必须是纯白（`Pure white background, no gradient`），不能是灰白渐变
- 生成后必须人工校验：数量是否正确、是否分离、背景是否纯净

### Step 6 — 质量校验与修正

**必检项清单：**

| 检查项 | 标准 | 处理方式 |
|--------|------|----------|
| 背景纯净度 | 纯白/透明，无网格、无渐变、无阴影 | 不达标则重生成，prompt中强化背景约束 |
| 附属结构数量 | 与设定文档完全一致 | 不达标则重生成，prompt中显式强调数量 |
| 附属结构分离度 | 多条尾巴/多个肢体必须清晰分开 | 不达标则重生成，prompt中强调"distinct""side by side""not merged" |
| 角色一致性 | 四张图的角色特征、配色、材质保持一致 | 轻微偏差可接受，严重偏差需重生成 |
| 视角准确性 | 正面/背面完全正对，侧视约30° | 角度偏差过大需重生成 |

**修正原则：**
- 发现问题立即重生成，不要尝试后期修图
- 重生成时prompt必须针对问题点显式强化约束
- 修正后的文件覆盖原存档，保留tmp目录中的历史版本备查

### Step 7 — 归档全部资产

将最终版四张视角图复制到角色专属文件夹，目录结构应为：

```
~/Desktop/{创作者姓名}/{角色名}/
├── {角色名}_正面.png
├── {角色名}_右侧.png
├── {角色名}_背面.png
├── {角色名}_左侧.png
├── {角色名}_最终渲染图.png    ← 标准参考图
└── {角色名}角色设定.md         ← 原始设定
```

## 四、后续使用规范

1. **标准参考图优先级**：`{角色名}_最终渲染图.png` 是所有后续生产的唯一视觉依据，任何偏离此图的修改需经确认。
2. **四视图用途**：四张无背景视角图直接供3D建模师作为角色 turnaround reference 使用，无需额外去底。
3. **设定变更流程**：若角色设定发生调整，应同步更新 `{角色名}角色设定.md` 并重新生成对应视图，保持文档与图像一致。
4. **版本管理**：角色专属文件夹内所有文件均为最终版，历史中间产物保留在 workspace `tmp/` 目录下备查。
5. **SOP迭代**：每完成一个新角色，若发现流程中有可优化的环节，应同步更新本文档。
